# API Changelog - Version 0.2.0

Version `0.2.0` introduces a complete curation of the library's public API surface. By design, it hardens the boundary between stable external integration interfaces and unstable internal execution modules, ensuring future additions or refactoring can occur with no breakage to library users.

---

## 1. Library Curation & Export Isolation

### Rationale
In version `0.1.0`, every module (`loader`, `parser`, `mapper`, `diff`, `spec`, `storage_schema`, `suppression`) was public. This exposed all internal types, collections, and helper functions directly to consumers. If the internal library changed a signature or switched internal data structures (e.g. from `HashMap` to `BTreeMap` to achieve stable ordering), it caused breaking changes for downstream consumers. 

In `0.2.0`, these modules are made private by default. Accessors and setters have been introduced to provide a clean stable facade, while advanced developers can opt into using the unstable modules by enabling the `unstable` feature flag.

### Crate Feature Configuration
*   **Default Behavior**: Modules are private (`mod` instead of `pub mod`).
*   **Unstable Feature**: Access to these modules is available behind the `unstable` feature flag:
    ```toml
    soroban-upgrade-safeguard = { version = "0.2.0", default-features = false, features = ["unstable"] }
    ```
*   **Crate Root Exports**: The stable public API is now clean and re-exported at the crate root level of `soroban-upgrade-safeguard`:
    *   Functions:
        *   `compare_wasm_bytes`
        *   `compare_wasm_bytes_with_options`
        *   `compare_wasm_bytes_with_storage_schemas`
        *   `compare_wasm_files`
        *   `compare_wasm_files_with_options`
        *   `compare_wasm_files_with_storage_schemas`
    *   Unified Types:
        *   `CompareOptions`
        *   `SafetyReport`
        *   `ReportedFinding`
        *   `Finding`
        *   `Severity`
        *   `AnalysisScope`
        *   `StorageScopeState`
        *   `ResourcePolicy`
        *   `LimitError`
        *   `SuppressionConfig`
        *   `SuppressionRule`
        *   `StorageSchema`

## 2. Transition from Direct Fields to Public Accessor Methods

### SafetyReport Encapsulation
Direct access to fields has been replaced with public getter methods to hide the internal data structures:
*   `critical_count` -> `critical_count() -> usize`
*   `warning_count` -> `warning_count() -> usize`
*   `info_count` -> `info_count() -> usize`
*   `suppressed_count` -> `suppressed_count() -> usize`
*   `suppressed_critical_count` -> `suppressed_critical_count() -> usize`
*   `total_findings` -> `total_findings() -> usize`
*   `is_safe` -> `is_safe() -> bool`
*   `strict` -> `strict() -> bool`
*   `scope` -> `scope() -> &AnalysisScope`
*   `baseline_source` -> `baseline_source() -> Option<&str>`
*   `verified_code_hash` -> `verified_code_hash() -> Option<&str>`
*   `old_spec_summary` -> `old_spec_summary() -> Option<&str>`
*   `new_spec_summary` -> `new_spec_summary() -> Option<&str>`
*   Direct access to the `findings_by_category` collection has been replaced with:
    *   `has_category(&self, category: &str) -> bool`
    *   `findings_for_category(&self, category: &str) -> Option<&[ReportedFinding]>`
    *   `categories(&self) -> impl Iterator<Item = &str>`

## 3. Future-Proofing with Non-Exhaustive Structs
Configuration structures are marked `#[non_exhaustive]` to ensure future field additions do not break standard struct literal initializations:
*   `CompareOptions`
*   `ResourcePolicy`
*   `SuppressionConfig`
*   `SuppressionRule`
*   `StorageSchema`
*   `DeclaredType`
*   `AnalysisScope`
